## Feature Description

The first files of the v2 engine, and the one spike the architecture pairs with its one-way door (D1).
Three things ship:

1. **The gate.** `package.json`, `tsconfig.json`, `biome.json`, `bun run check` = `tsc --noEmit` +
   `biome check .` + `bun test`, with one passing test. The stop hook switches from `pnpm check` to
   `bun run check` and from the taxi repo's folders to this repo's.
2. **A hello-world binary.** `src/server.ts` is a `Bun.serve` on `127.0.0.1` that takes the first free
   port from a fixed list, falls back to any free port, prints the URL and opens the browser on one page.
3. **The zips.** `scripts/build.ts` runs `bun build --compile` for Windows x64, macOS arm64 and macOS x64
   and writes `dist/StudyTutor-windows.zip` and `dist/StudyTutor-mac.zip`, each with its launcher
   (`Start.bat`, `Start.command`) and a ten-line `README.txt`.

Then the spike: a non-technical adult goes from zip to first page on a fresh Mac and a fresh Windows PC,
timed. The result and the port answer (Q11) go into the architecture doc.

## User Story

As a parent with a fresh Mac or Windows PC
I want to download one zip, open one thing, and see the tutor's page in the browser
So that the family can run the tutor without a developer, an installer or a Terminal

As Linards
I want the S1 answer (does an unsigned Bun binary plus a launcher get a parent to the first page in under
ten minutes with no dead end) before any engine code exists
So that D1, the one decision with low reversibility, is tested at its worst edge for half a day's work

## Problem Statement

Architecture D1 commits the whole engine to a compiled local app. Its worst edge is not the code; it is
Gatekeeper and SmartScreen on a machine the developer does not control, with no signing (PRD non-goal, D10).
Nothing has been built on Bun in this repo yet, and there is no gate: the stop hook still runs `pnpm check`
against `apps/ services/ packages/ db/`, none of which exist here, so it never fires (`observed`:
`.claude/hooks/stop_check.py:31`, `CODE_PREFIXES = ("apps/", "services/", "packages/", "db/")`).

## Solution Statement

Scaffold the repo from the tool templates, add the smallest server that exercises the three things S1
cares about (bind, port pick, browser open), compile it for the three targets from this Mac (cross-compile
`observed` working, see Notes), zip with launchers that reduce the OS prompts to the minimum a parent must
click through, and run the spike protocol in Level 4. Record the result in the architecture doc.

### Patterns to Follow

**Config shapes (all `observed` green on the sketch, 2026-09-27):**

`tsconfig.json` is the `bun init` template verbatim with one line added after `"noEmit": true,`:

```json
"types": ["bun"],
```

Without it TypeScript 7.0.2 cannot see `Bun`, `Response`, `process` or `import.meta.main` (`observed`: 23
errors, then 0 with the line).

`biome.json`:

```json
{
  "$schema": "https://biomejs.dev/schemas/2.5.14/schema.json",
  "vcs": { "enabled": true, "clientKind": "git", "useIgnoreFile": true },
  "files": { "ignoreUnknown": false, "includes": ["**", "!!e1", "!!dist"] },
  "formatter": { "enabled": true, "indentStyle": "space", "indentWidth": 2 },
  "linter": { "enabled": true, "rules": { "preset": "recommended" } },
  "javascript": { "formatter": { "quoteStyle": "double" } },
  "assist": { "enabled": true, "actions": { "source": { "organizeImports": "on" } } }
}
```

Spaces, not Biome's default tabs, because the v1 donor code that `app/` and `content/` will carry over is
two-space (`observed`: `e1/assets/case.js` has 94 two-space-indented lines and 0 tab-indented). `e1` is
force-ignored because it is the v1 folder's copy, not v2 code (`observed`: with `e1` included Biome
reports its files; with `!!e1` it checks 5 files and reports nothing).

**Port pick (the sketch that passed):**

```ts
export const PORTS = [4731, 4732, 4733, 4734, 4735] as const;

export function startServer(ports: readonly number[]) {
  for (const port of ports) {
    try {
      return Bun.serve({ hostname: "127.0.0.1", port, fetch: handle });
    } catch (err) {
      // Windows answers with EACCES, not EADDRINUSE, for a port inside a Hyper-V or WSL
      // excluded range; step past that too. Port 0 failing is not a ladder case.
      const code = (err as { code?: string }).code;
      if (port === 0 || (code !== "EADDRINUSE" && code !== "EACCES")) throw err;
    }
  }
  throw new Error(`No free port in ${ports.join(", ")}`);
}
```

`Bun.serve` on a taken port throws synchronously with `code === "EADDRINUSE"` and message `Failed to
start server. Is port 4731 in use?` (`observed`, Bun 1.3.4). The production call is
`startServer([...PORTS, 0])`: the fixed list first so the URL is stable for bookmarks and for T10's MCP
config, then `0` so a parent never hits a dead end when all five are taken.

**Entry guard:** `if (import.meta.main) { ... }` is `true` when the file is run directly and inside the
compiled binary (`observed`: the compiled sketch printed its URL and answered `curl` with 200), and
`false` when the test imports it. Every side effect (bind, print, browser) lives inside that block.

**Browser open:** `Bun.spawn(cmd, { stdio: ["ignore", "ignore", "ignore"] })` with
`["open", url]` on darwin, `["cmd", "/c", "start", "", url]` on win32, `["xdg-open", url]` otherwise.
The empty `""` after `start` is the window title argument; without it `start` treats the URL as the title.
Darwin `observed` (the sketch opened a tab); win32 `expected`.

**Naming:** files kebab-case, exports camelCase, constants SCREAMING_CASE, as in `CLAUDE.md`'s map.

**Pupil-facing and parent-facing text:** British English, sentence case, no exclamation marks, no emoji
(`.claude/rules/content.md`). Applies to the hello page, the console line and `README.txt`.

## TESTING STRATEGY

### Unit Tests

`src/server.test.ts` (Task 3) covers the port ladder, the last-resort `0`, the page and the 404. Framework
`bun:test`. Nothing else in this ticket is unit-testable in a useful way: `openBrowser` spawns a program

### Integration Tests

None in code. The compiled binary run from the extracted zip (Task 5's VALIDATE) is the integration check:
it proves `import.meta.main`, the bind, the port and the launcher permissions through the real artefact.

- All five fixed ports taken → `port: 0` → verified in `src/server.test.ts` (Task 3).
- A port taken → next in the list → `src/server.test.ts`.
- `Start.bat` opened inside the zip preview → message and `pause` → Level 4 step 4c (manual; no test
  framework reaches cmd on Windows from here).
- `Start.command` on an Intel Mac → picks `StudyTutor-x64` → Task 5's VALIDATE on this machine.
- `Start.command` on Apple silicon → picks `StudyTutor-arm64` → Level 4 step 5 (the fresh Mac).

  observation to record).
- `zip` missing at build time → refusal message → `PATH=/usr/local/bin bun scripts/build.ts` prints the
  message and exits 1 (Task 5, run once by hand).

## OPEN QUESTIONS / ASSUMPTIONS

- **Q1 (decided 2026-09-27: heredoc).** `.claude/hooks/stop_check.py` is fenced by guard 6 for Edit/Write. The
  ticket asks for the change, and the guard's docstring names a Bash heredoc as the deliberate path.
  Recommended: the implementer rewrites it with a heredoc and says so in the report. Alternative: the
  implementer prints the full new file and you paste it in. Either way the file changes; the question is
  who types it.
- **Q2 (decided 2026-09-27: keep the line).** `Start.command` runs `xattr -d com.apple.quarantine` on
  the binary before executing it, so the parent meets Gatekeeper once (for the script) rather than twice.
  Without it the worst case is two rounds of System Settings and two relaunches, which is likely a dead
  end by S1's rule. The script itself still needs Open Anyway; the line does nothing to that. If you would
  rather measure the raw path, remove the line and the README keeps the same words.
- **Q3 (decided 2026-09-27: both binaries).** The mac zip carries both arm64 and x64 binaries (about 50 MB, `expected`) and the
  launcher picks by `uname -m`. Reason: this dev Mac is Intel (`observed`: `process.arch === "x64"`,
  macOS 15.7.3), so x64 is the only build testable here, while a fresh family Mac is most likely Apple
  silicon. arm64-only would halve the zip and leave Intel Macs to Rosetta, which prompts to install itself
  on first use: one more dialog. Cut to one target later if the size matters.
- **Q4 (decided 2026-09-27: `launchers/`).** Launchers live in `launchers/` rather than at the repo root as the ticket's file
  list says. Reason: a root `README.txt` would become the GitHub landing page (there is no `README.md`),
  and `build.ts` copies from one folder. Flag in the PR body.
- **Q5 (assumption).** A ten-line `README.txt` ships in the zip now although first-run docs are T11's.
  Without it the timed adult has no instructions and the spike measures nothing. T11 replaces it.
- **Q6 (worst-case ordering).** The parent double-clicks `Start.command` a second time while the first
  binary is still running (the Terminal window from the first run is open). Worst case: the second run
  takes 4732 and opens a second tab; nothing breaks, two windows are open. Acceptable for S1; T11's docs
  say "close the window that started the tutor".
- **Q7 (worst case, Windows).** The Windows PC has Smart App Control on (new Windows 11 installs may). The
  `.bat` is blocked with no Run anyway. Recorded as a dead end for that machine; the fallback is
  double-clicking `StudyTutor.exe`, which SmartScreen allows through More info → Run anyway
  (`expected`). If that happens, S1's rule reads "Windows first" is not even safe, and the architecture
  needs a note: the exe must be openable on its own, so the console must show the URL, which it does.
- **Assumption.** TypeScript 7.0.2 is what `bun add -d typescript` installs today and `tsc --noEmit`
  passed on the sketch with the `bun init` tsconfig plus `"types": ["bun"]`. If a later `bun install`
  pulls a 7.x that rejects an option in that template, pin `typescript@^5` and say so; nothing else
  changes.
